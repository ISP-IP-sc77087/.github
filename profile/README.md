<h2>采购决策其实只有五个问题，问完就能下单</h2>
<p>面对一份双 ISP 住宅 IP 的报价，需要确认的东西看起来很多：地区、类型、独享、带宽、地址数、周期、运维。但真正影响决策的只有五个：地址是不是真的双 ISP、是不是你独享、上行够不够、能不能长期续、出问题谁来处理。</p>
<p>其余参数都是这五个的衍生。先问这五个，能省掉大量来回。</p>

<h2>第一个问题：地址是不是真的双 ISP</h2>
<p>这是最容易含糊的一项。要求对方给出两个运营商的查询结果，并分别核对这两个主体是不是当地真实存在的宽带服务商。如果其中一个查不到实体，那这个「双」只是数据库里的一条记录。</p>

<h2>第二个问题：是不是你独享</h2>
<p>共享和独享的差别不在速度，在「你能控制多少变量」。共享资源上，同段其他人的行为会直接影响这条地址的表现和评价，而你对此毫无办法。</p>
<p>判断方法：直接问「这条地址现在还有别人在用吗」，看对方回答的具体程度。愿意明确说「独享」并写进条款的，可信度更高；回答「基本没人用」这种模糊表述的，按共享对待。</p>

<h2>第三个问题：上行够不够</h2>
<p>双 ISP 住宅资源的上行普遍小于下行，而很多业务恰恰卡在上行。做素材上传、直播推流、批量同步的，必须实测上行，不能只看标称带宽。</p>
<p>实测方法很简单：在业务高峰时段上传一个几百兆的文件，计时算速度。这个数字比任何标称值都可靠。</p>

<h2>第四个问题：能不能长期续、续了地址变不变</h2>
<p>双 ISP 的价值在于「稳定且特殊」，如果续费时地址换了，前面为它做的环境配置全部作废，溢价也就白付了。这一条必须在付款前确认，最好写进约定。</p>
<p>另外要问「能不能保证不涨价」。续费涨价很常见，提前问清能避免第二个月的成本冲击。</p>

<h2>第五个问题：出问题谁来处理</h2>
<p>资源不可能永不出问题。关键是有问题时的响应路径：找谁、多久回、能不能换。这一项在报价单上通常没有，但它决定了你买到的是一份资源还是一份麻烦。</p>
<p>问法可以具体一点：「如果这条地址突然不可用，你们的处理流程是什么，平均多久给替换」。回答得越具体，说明对方越有准备。</p>

<h2>配置怎么选：三个原则</h2>
<p>一是够用加余量，不要一次配到很足。二是瓶颈在哪里就把钱花在哪里，先测再升。三是稳定性优先于峰值，长期运行的机器稳定比跑分重要。</p>
<p>这三点在双 ISP 场景里尤其适用，因为这类资源的价格本就不低，配置上的浪费会被放大。</p>

<h2>价格怎么判断：三件事</h2>
<p>一是把一次性费用摊进首月。开通费、地址费常常不在月费里，加起来可能差出一截。二是确认续费价。三是拿同参数问三家，取中间区间。</p>
<p>如果某家明显低于区间，先问它在五个决策项里让步了哪一项。愿意说明的可以谈，说不清的就按风险最高估。</p>

<h2>一个容易漏掉的成本</h2>
<p>管理成本。双 ISP 资源通常意味着更复杂的配置（两个出口、策略路由、健康检查），需要有人懂这些。如果团队里没人能维护，那这部分要么外包、要么自己学，都是成本。</p>
<p>采购时把这块算进去，才不会出现「买得起但用不起来」的情况。</p>

<h2>常见问答</h2>
<h3>双 ISP 一定比单 ISP 好吗？</h3>
<p><strong>答：</strong>不是。它提供的是一种网络特征，需不需要取决于业务。不需要时就是纯溢价。</p>
<h3>配置需要很高吗？</h3>
<p><strong>答：</strong>不需要。转发类任务对配置要求不高，重点是网卡与稳定性。</p>
<h3>能先买一条试吗？</h3>
<p><strong>答：</strong>多数可以。试的时候把五个决策项都验证一遍，别只测速度。</p>
<h3>价格差一倍，该选哪个？</h3>
<p><strong>答：</strong>先看差在哪个决策项上。如果差在独享与运维，那贵的有道理；如果只是渠道加价，可以再谈。</p>
